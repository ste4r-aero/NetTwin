# NetTwin — локальный сетевой комбайн для системного администратора

**NetTwin** — это «швейцарский нож» сисадмина, который живёт на вашем ноутбуке с Arch Linux и работает через браузер по адресу `http://localhost:8080`. Он умеет:

- 🔌 **Живой тестер кабеля** — мгновенно показывает скорость/дуплекс/линк USB-Ethernet адаптеров (карточка светится зелёным / жёлтым / красным);
- 🗺 **Пассивный радар + карта сети** — сам «услышивает» устройства в комнате (ПК, принтеры, свитчи, камеры) и рисует карту комнат, ничего не отправляя в сеть;
- 📋 **Паспорта ПК** — однофайловый скрипт-агент для флешки (Windows `.bat` / Linux `.sh`) собирает модель, серийник, CPU, RAM, MAC и присылает их на ноутбук;
- ❓ **Встроенная справка** — весь этот гид доступен прямо в интерфейсе, вкладка «Справка».

---

## 🛡 Главный принцип: абсолютная безопасность для корпоративной сети

NetTwin **полностью пассивен**. Это железное правило зашито в архитектуру:

- ❌ **Запрещено и отсутствует**: `nmap`, `arp-scan`, `fping`, ICMP-пинги, TCP/UDP-сканирование, отправка любых зондов;
- ✅ **Единственный способ поиска устройств** — прослушивание трафика, который **и так летает в сети**: BPF-фильтр `arp or udp port 5353 or udp port 67 or ether proto 0x88cc` (ARP, mDNS, DHCP, LLDP);
- 🔇 Режим прослушивания — **не promiscuous** по умолчанию: ноутбук выглядит для сети как молчащий слушатель, поэтому корпоративные IDS/IPS, системы обнаружения сканеров и port-security на свитчах **не видят никакой активности**;
- 🌐 Всё работает локально: без облаков, без телеметрии, без внешних серверов.

> Проще говоря: NetTwin ничего не «спрашивает» у сети — он только слушает, как устройства сами представляют друг другу себя.

## 🚀 Установка с нуля (пошагово)

Всё, что нужно — один раз поставить Docker. Дальше — одна команда.

### Шаг 0. Поставить Docker (один раз)

Откройте терминал (`Konsole` / любой) и выполните:

```bash
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker     # запустить сейчас + автозапуск при загрузке
sudo usermod -aG docker semen          # разрешить пользователю semen работать с Docker
```

> ⚠️ После `usermod` **обязательно выйдите из системы и войдите снова** (или перезагрузите ноутбук) — иначе Docker будет ругаться на права.

Проверка: команда `docker ps` не должна писать `permission denied`.

### Шаг 1. Запустить установщик

```bash
cd ~/NetTwin          # папка проекта (положите её, например, в /home/semen)
./install.sh
```

Установщик сам:
1. проверит Docker и службу `docker.service` (и подскажет на русском, что сделать, если что-то не так);
2. соберёт и запустит контейнер в фоне (`docker compose up -d --build`) с политикой `restart: unless-stopped` — после перезагрузки ноутбука всё поднимется само;
3. дождётся ответа `http://localhost:8080` (до 2 минут);
4. создаст ярлык **NetTwin** на рабочем столе (`~/Desktop/NetTwin.desktop`) и сделает его исполняемым.

### Шаг 2. Открыть приложение

- ярлык **NetTwin** на рабочем столе (двойной щелчок), или
- браузер → `http://localhost:8080`.

Готово. Больше никаких ручных действий не требуется — никогда.

## 🧭 Как работать в офисе

### 🔌 Проверка кабеля (витой пары)

1. Один конец кабеля — в проверяемый порт (свитч/ПК), второй — в USB-Ethernet адаптер ноутбука.
2. Вкладка **«Тестер кабеля»**. Карточка адаптера загорится через 1–2 секунды:
   - 🟢 **зелёный, 1000 Мбит/с** — кабель обжат всеми 8 жилами, всё отлично;
   - 🟡 **жёлтый, 10/100 Мбит/с** — линк есть, но гигабита нет: проверьте обжим всех 8 жил на обоих концах (коннекторы RJ-45, распиновка T568B) и настройку порта свитча;
   - 🔴 **красный** — линка нет: кабель не вставлен / пережат / перепутаны пары / порт выключен.
3. На карточке видны: IP и маска, шлюз, DNS, чип USB-адаптера, LLDP-сосед (для управляемых свитчей) и текущий трафик.
4. Кнопка **«💾 Сохранить замер»** — фиксирует результат с вашей заметкой («кабель №14, патч-панель 2») в истории ниже.

### 🗺 Съём комнаты через неуправляемый свитч

1. Придите к свитчу, воткните патч-корд из его свободного порта в USB-адаптер ноутбука.
2. Вкладка **«Карта сети»**, панель справа **«Я сейчас у точки / свитча»**.
3. Введите название (например, *«Отдел Упаковка — Свитч №1»*), выберите адаптер и нажмите **«Слушать точку (30 сек)»**.
4. Всё, что радар услышит за это время (ПК «болтают» по ARP/mDNS/DHCP сами), автоматически рисуется вокруг иконки свитча и соединяется линиями.
5. Дальше расставьте узлы мышкой (позиции сохраняются сами), создайте **🏠 комнату** и перетащите устройства внутрь, подпишите и раскрасьте кабели (клик по линии → панель справа). Рекомендация: жёлтый = плохой обжим, зелёный = проверен.
6. Если в комнате тихо — попросите коллег включить ПК или отправить печать, либо повторите прослушивание.

### 🪪 Паспорт нового ПК

1. Вкладка **«Паспорта»** → **«⬇ Агент Windows (.bat)»** (или Linux `.sh`) — скрипт сохранится в загрузки. Скопируйте его на флешку (удобно с Ventoy).
2. На новом ПК запустите скрипт двойным щелчком:
   - если ноутбук NetTwin доступен по сети — паспорт улетит мгновенно и появится в таблице;
   - если сети нет — скрипт сохранит JSON-файл рядом с собой. Привезите файл и загрузите кнопкой **«⬆ Импорт»** вверху экрана.
3. **«Экспорт CSV»** — таблица для Excel/отчётов (кириллица открывается корректно).

## 💾 Резервная копия

- **⬇ Бэкап** (вверху справа) — один JSON-файл со **всей** картой: устройства, узлы, связи, комнаты, замеры, LLDP. Копируйте на флешку после каждой смены.
- **⬆ Импорт** — восстановление. Режим «объединить» — дописать к текущей карте; «заменить» — точное восстановление состояния на момент бэкапа.
- Файл базы данных лежит в `NetTwin/data/nettwin.db` — можно просто скопировать его целиком.

## ⚙️ Управление (копируйте команды)

Все команды выполняются из папки проекта (`cd ~/NetTwin`):

| Что нужно | Команда |
|---|---|
| Посмотреть логи | `docker compose logs -f nettwin` |
| Перезапустить | `docker compose restart nettwin` |
| Остановить | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Обновить приложение после правок кода | `./install.sh` (пересоберёт и перезапустит) |
| Проверить состояние | `docker compose ps` и `curl http://localhost:8080/api/health` |

### Полное удаление

```bash
cd ~/NetTwin
docker compose down            # остановить контейнер
docker rmi nettwin:latest      # удалить образ (необязательно)
cd ~ && rm -rf ~/NetTwin       # удалить проект вместе с базой данных
rm ~/Desktop/NetTwin.desktop ~/.local/share/icons/nettwin.svg
```

Docker при этом остаётся в системе (его можно удалить отдельно: `sudo pacman -Rns docker docker-compose`).

## 🔧 Частые вопросы и неполадки

| Симптом | Причина и решение |
|---|---|
| `install.sh` пишет «Служба docker не запущена» | `sudo systemctl enable --now docker` и запустить установщик снова |
| `permission denied` при работе с Docker | Вы не вышли из системы после `usermod -aG docker semen`. Выйдите/войдите или перезагрузитесь |
| Первый запуск долгий | Нормально: Docker скачивает образ Python и библиотеки. Нужен интернет только на время сборки |
| Сервер не поднялся, порт занят | Посмотрите логи `docker compose logs -f nettwin`. Если порт 8080 занят другим приложением — поправьте порт в `docker-compose.yml` (`NETTWIN_PORT` и `CMD` в Dockerfile) |
| В «Тестере кабеля» пусто | Воткните USB-адаптер — карточка появится сама в течение пары секунд. Адаптеры должны называться `en*` (стандартные имена Arch) |
| Радар никого не находит | Убедитесь, что кабель воткнут в **рабочий порт свитча** (карточка тестера зелёная). В тихой комнате попросите коллег включить ПК. Помните: NetTwin ничего не «пингует» сам — только слушает |
| Неверный производитель устройства | Встроенная офлайн-база OUI компактна. Положите официальный файл IEEE в `data/oui_extra.txt` (формат `00-1B-A1 (hex) НАЗВАНИЕ` или `001BA1\|HP\|pc`) и перезапустите контейнер |
| Браузер открыл пустую страницу | Убедитесь, что открываете именно `http://localhost:8080` (не https) |
| Изменился IP ноутбука | Ничего страшного: агентские скрипты пересоздаются кнопкой — в них подставится текущий IP |

## 🧩 Технические детали (для любопытных)

- **Контейнер**: `network_mode: host` + `cap_add: [NET_ADMIN, NET_RAW]` — прямой доступ к интерфейсам хоста без NAT, сниффер видит `en*` адаптеры как есть.
- **L1/L2 тестер**: `ethtool` (Speed/Duplex/Link detected) + `ip -j addr/route` (IP, маска, шлюз) + `/sys/class/net/*/statistics` (трафик) — опрос каждые 2 секунды, поток через WebSocket `/ws/interfaces`.
- **Радар**: по одному слушающему сокету на каждый `en*` интерфейс (адаптеры можно втыкать на ходу — подхватятся автоматически); ARP даёт пары IP↔MAC, mDNS — имена/модели принтеров, DHCP — имена хостов + шлюз/DNS, LLDP/CDP — соседние управляемые свитчи.
- **Определение типа устройства**: по OUI (вендор MAC) + по mDNS-сервисам (`_ipp._tcp` → принтер) + по LLDP capabilities. Тип всегда можно поправить вручную во вкладке «Паспорта».
- **База**: SQLite (WAL) в `data/nettwin.db`, все позиции узлов и связи сохраняются мгновенно.
- **REST API**: документация Swagger доступна на `http://localhost:8080/api/docs`.

*Проект собран для локального использования одним администратором. Приятной работы!*
